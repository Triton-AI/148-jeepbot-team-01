Overview What you're setting up

JeepBot is a dual-VESC autonomous RC platform. One VESC steers (a motor + encoder driven by position commands), the other drives the wheels (duty-cycle). An OAK-D Pro camera and a Flask web UI run as in-process threads of the drive loop, recorded data lands in a tub/, and a trained CNN can take over steering or full driving.

The whole thing launches from a single command — python3 myconfig.py drive — which reads myconfig.py for every hardware-specific value. A fresh start is five sequential steps:

  1. Environment & clone — a Python virtualenv and the repo.
  2. Install requirements — runtime deps on the Pi, training deps on your laptop.
  3. Configure — serial ports, controller, cameras in myconfig.py.
  4. Drive — run it, open the web UI, check your controls.
  5. Record & train — collect laps, train a pilot, deploy it back.

Hardware & parts What's on the car

  • Raspberry Pi — runs the drive loop, cameras, and web server
  • 2× VESC — one for steering (motor + encoder, position control), one for drive (duty-cycle, 4WD)
  • 2× OAK-D Pro — front and rear depth cameras
  • Controller — Logitech F710 (USB dongle) or a RadioMaster radio via an Arduino Leonardo
RadioMaster?If you're driving with the ExpressLRS radio instead of the F710, flash the TX/RX and the Leonardo first — that's covered in the separate ELRS controller guide. Then set CONTROLLER = "radiomaster" here.

01

Environment & clone venv + git

Always work inside a virtual environment so JeepBot's dependencies stay separate from the system Python.

terminal
python3 -m venv ~/jeepbot-env
source ~/jeepbot-env/bin/activate

git clone https://github.com/KennethKhant/JeepBot-SetUp.git myjeepbot
cd myjeepbot
Every terminalYou have to source ~/jeepbot-env/bin/activate in each new shell before running JeepBot. Add that line to the end of ~/.bashrc to activate it automatically on login.

The repo is code only — recorded tub/ images and trained models/ aren't committed (just .gitkeep placeholders), so the clone is small and you begin with an empty data set.

02

Install requirements pip

Which file you install depends on the machine's job.

On the Raspberry Pi — runtime

raspberry pi · terminal
pip install -r requirements_pi.txt
pip install -e .

requirements_pi.txt pulls in pygame, pyserial, flask, numpy, opencv-python, and depthai (the OAK-D driver). The pip install -e . registers the bundled PyVESC so the drive script can import pyvesc — do this once per environment.

On your laptop / desktop / Jetson — training

training machine · terminal
pip install -r requirements_train.txt

This installs numpy, opencv-python, and tensorflow for jeep_train.py.

Running AI on the PiThe Pi requirements have no TensorFlow — the Pi normally only runs the model. If you intend to run auto_steering / full_drive directly on the Pi, you may need to install TensorFlow there too.
03

Configure myconfig.py Everything hardware-specific

On a fresh machine, confirm these before driving.

Serial ports (VESCs)

  • DEFAULT_STEERING_PORT/dev/ttyACM1
  • DEFAULT_DRIVE_PORT/dev/ttyACM0

ACM0/ACM1 can swap on reboot or by plug order. List what's connected, and test wiring safely without opening the VESC ports using a dry run:

terminal
# which serial ports exist
python3 myconfig.py drive --list-ports

# read the controller without touching the motors
python3 myconfig.py drive --dry-run

If steering and drive are reversed, swap the two port values (or replug).

Controller

  • CONTROLLER"f710" or "radiomaster"

Both profiles live in controller_profiles.py. If sticks map to the wrong axis, find the right indices by wiggling one control at a time and reading which index changes:

terminal
python3 controller_axes_test.py

Then set steering_axis / drive_axis / deadman_button in that controller's profile.

DeadmanThe deadman button must be held for any command to be sent — releasing it stops the car. That's intentional. Don't disable it on the bench unless you mean to.

Cameras (OAK-D Pro)

  • SWAP_CAMERASTrue — flip if front/rear are reversed
  • FRONT_CAMERA_MXID"" — pin to a serial for reliability
  • REAR_CAMERA_MXID""

With two OAK-D cameras, discovery order isn't guaranteed across reboots. The robust fix is to pin each camera to its serial (MxId). List the connected serials:

terminal
python3 -c "import depthai as dai; print([d.getMxId() for d in dai.Device.getAllAvailableDevices()])"

Paste them into FRONT_CAMERA_MXID / REAR_CAMERA_MXID.

YOLO overlay (optional)

YOLO runs from its own virtualenv (ultralytics is heavy, kept separate). Activate it before driving if you want detection; otherwise set ENABLE_YOLO_DETECTION = False.

terminal
source /home/jeepbot/yolo-test/bin/activate

1. Record on the Pi

Drive in record mode. Each run creates a timestamped session under tub/ (e.g. tub/session_20260602_191728/) with images and the matching steering/throttle values. Collect varied, clean laps — the model only learns what you show it.

2. Copy the tub to your training machine

laptop · terminal
scp -r jeepbot@<pi-ip>:~/myjeepbot/tub ./tub

3. Train

laptop · terminal
# train on everything in tub/
python3 jeep_train.py --tub tub --model models/jeep_pilot.keras

# train on a single session
python3 jeep_train.py --tub tub/session_20260521_200737 --model models/jeep_pilot.keras

# fine-tune an existing model
python3 jeep_train.py --tub tub --model models/jeep_pilot.keras --base models/jeep_pilot.keras

Flags: --epochs (default 100), --batch (64), --val-split (0.15), --no-aug to disable augmentation.

4. Deploy the model back to the Pi

laptop · terminal
scp models/jeep_pilot.keras jeepbot@<pi-ip>:~/myjeepbot/models/

The drive script loads DEFAULT_MODEL_PATH = "models/jeep_pilot.keras". Switch to auto_steering or full_drive in the web UI to let it take over.

Troubleshooting When it doesn't just work

could not open port /dev/ttyACM0

The VESC isn't on that port. Run --list-ports, update DEFAULT_DRIVE_PORT / DEFAULT_STEERING_PORT, and check the cable. You may also need permission — add yourself to the dialout group with sudo usermod -aG dialout $USER, then log out and back in.

Car doesn't move / no commands sent

You're not holding the deadman button, or its index is wrong for your controller. Confirm with controller_axes_test.py and set deadman_button in the controller profile.

Steering goes the wrong way

Set invert_steering (or invert_drive) in the controller profile, or flip DEFAULT_INVERT_STEERING in myconfig.py.

Front/rear cameras swapped

Toggle SWAP_CAMERAS, or pin both with FRONT_CAMERA_MXID / REAR_CAMERA_MXID.

No camera found / DepthAI errors

Only one process can hold an OAK-D at a time. Make sure no other script (or a crashed previous run) is still using it — the camera and web server are meant to run as in-process threads of the drive loop, not as separate processes.

AI modes do nothing

DEFAULT_MODEL_PATH points at a model that doesn't exist yet. Train one and copy it to models/jeep_pilot.keras.
